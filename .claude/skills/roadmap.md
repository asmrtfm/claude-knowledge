Review the current ROADMAP.md, then discuss the user's idea with them.

## Rules

- **One point at a time.** Present a single item for discussion, wait for the user's decision, then WRITE it to `ROADMAP.md` BEFORE moving on to the next item. Never batch — each decision is recorded immediately.
- **Only update the roadmap.** This skill is for documenting decisions, not implementing them. Never create, edit, or delete project files other than `ROADMAP.md`.
- **Discuss, don't rubber-stamp.** Ask clarifying questions if the scope or intent isn't clear. Suggest trade-offs. But once the user decides, record it and move on.

## Steps

1. Read `ROADMAP.md` in the project root to understand what's already planned, under consideration, and completed.

2. Present the first point of discussion. Wait for the user's response.

3. After the user decides on the point, immediately update `ROADMAP.md`:
   - **Active** — if we've agreed on scope and it's ready to implement
   - **Considering** — if the idea is solid but needs more thought or depends on other work
   - Use a bold title, a 1-2 sentence description capturing the what and why, and the current date
   - Include the user's specific decisions and rationale

4. Then present the next point. Repeat steps 2-3 until all points are covered.

5. If an item relates to or supersedes an existing roadmap item, update or move that item rather than duplicating.
